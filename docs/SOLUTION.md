# Финальное решение v45

## 1. Формализация

Для каждой карточки известна заявленная категория и требуется предсказать бинарную метку качества:

- `1` — товар соответствует правилам категории (`не бан`);
- `0` — не соответствует (`бан`).

Официальная метрика — положительный F1 отдельно для `БАД` и `Легковоспламеняющиеся`, затем их среднее. Поэтому единый глобальный порог некорректен: категории различаются и по правилам, и по балансу классов.

| Категория | label=0 | label=1 | Positive rate |
|---|---:|---:|---:|
| БАД | 1 905 | 5 564 | 74.50% |
| Легковоспламеняющиеся | 5 304 | 198 | 3.60% |

## 2. Входной контракт

Каждая строка приводится к канонической структуре:

```text
id, title, description, category, images[], label?, entity_group?
```

Пути к изображениям разрешаются относительно входного файла. Для официальных данных изображения автоматически находятся в `images/<id>/`. Неизвестные категории отклоняются, а порядок ID защищён при выравнивании embedding cache.

## 3. Leakage-aware validation

Обычный random split оказался бы оптимистичным: в данных 3 467 дубликатов составного текста и повторяющиеся изображения. `entity_group` соединяет карточки по:

- нормализованному title;
- полному тексту, его head/tail шаблонам;
- консервативной сигнатуре главного изображения.

Все OOF и holdout-разбиения сохраняют группы целиком. В фиксированном holdout нет пересечений ID или entity groups. Для редкой категории решение дополнительно проверялось на пяти outer group-folds; разброс F1 по folds документирован в [VALIDATION.md](VALIDATION.md).

## 4. Lexical-ветка

Название, описание и категория преобразуются в объединение:

- word TF-IDF, n-grams 1–2;
- char TF-IDF, n-grams 2–5;
- небольшое число category-specific rule tokens.

Для каждой категории обучается отдельная Logistic Regression с class weighting. Эта ветка сохраняет точные маркировки `БАД`, `dietary supplement`, названия газов, артикулы и опечатки, которые dense embedding может сгладить.

## 5. VLM-ветка

Используется `Qwen/Qwen3-VL-Embedding-2B` из разрешённого списка:

```text
system instruction
category + name + description + main image
                    ↓
model-card chat template
                    ↓
last non-padding token, L2 normalization
                    ↓
category-specific Logistic Regression
```

Важная инженерная деталь: ранняя реализация вручную добавляла vision tokens и применяла masked mean. Переход на model-card chat contract и last-token pooling вместе с восстановлением полного image corpus дал основной прирост v8.

## 6. OOF blend

Lexical и VLM вероятности объединяются отдельно для каждой категории. На train OOF перебираются вес VLM и две стратегии:

- обычное среднее вероятностей;
- среднее logit-margin относительно собственных OOF-порогов веток.

Holdout не участвует в выборе веса или порога. После фиксации решений обе головы переобучаются на всех 12 971 размеченных строках.

## 7. Reference kNN для воспламеняемых

У редкой категории всего 198 положительных строк и 113 положительных entity groups. Линейная голова плохо сохраняет редкие семейства, поэтому v19 добавляет nearest-reference сигнал в том же Qwen3-VL пространстве.

Для запроса `x` вычисляется:

```text
s(x) = max cosine(x, positive references)
     - max cosine(x, negative references)
```

Итоговый margin:

```text
m = (1 - α) · (logit(p_base) - logit(t_base))
  + α · (s(x) - t_knn) / scale

p_final = sigmoid(m)
```

Для v19 заморожены `α=0.3`, `scale=0.01`, `blend_threshold≈0.26`. Параметры выбраны по repeated 5-fold group OOF с seeds `41, 43, 47, 51, 59` и сохранены в [configs/v19_knn.json](../configs/v19_knn.json). В full-data artifact попадает reference bank из всех размеченных карточек только после фиксации параметров.

### Почему kNN, а не более сложная обучаемая голова

Это был эмпирический выбор, а не исходное предположение. Редкий класс состоит из
нескольких семантически далёких семейств при 113 независимых positive groups.
Локальный reference score сохраняет такие острова в embedding space, тогда как
единая линейная граница склонна их сглаживать.

| Кандидат | Проверка | Результат | Решение |
|---|---|---:|---|
| v10 без retrieval | public Macro F1 | `0.793388` | основа |
| v19 reference kNN | public Macro F1 | `0.808892` | выбран, `+0.015504` |
| standardized head | flammable outer F1 | `0.681818` | оставлен только как слабый дополнительный сигнал |
| RBF SVC | flammable outer F1 | `0.674221` | без прироста к v19 |
| Qwen3.5 hidden head | flammable outer F1 | `0.676140` | не оправдал второй encoder на inference |
| Qwen3-VL LoRA | hard-fold AP | `0.209187` | хуже v19 `0.363317`, отклонён |

kNN переиспользует те же Qwen3-VL embeddings и добавляет только reference bank
в classifier artifact. Его цена — около 28 МБ артефакта, а не запуск второй
нейросети.

## 8. Стандартизованная линейная голова

v19 остаётся основой финального решения. В v45 для категории `Легковоспламеняющиеся` к нему добавлена ещё одна простая голова над исходными joint embeddings:

```text
raw Qwen3-VL embedding
        ↓
StandardScaler, обученный только на released train
        ↓
balanced Logistic Regression, C=0.03
        ↓
logit-blend с v19, α=0.25, threshold=0.26
```

Гиперпараметры были выбраны до full refit по repeated group OOF, fixed holdout и outer group check. В финальном артефакте scaler и Logistic Regression переобучены на всех 5 502 карточках редкой категории. Замороженные параметры хранятся в [configs/v45.json](../configs/v45.json).

## 9. Пять узких правил и их реальный вклад

Последний слой v45 — пять узких title-regex для товарных семейств, однозначно следующих из определения задачи: самостоятельные уголь/топливные брикеты, одноразовый мангал с углём, газ для портативной плиты или горелки, дымовая шашка и брикеты для барбекю. На released data эти правила покрыли 39 примеров без false positive.

Важнее того, что включено, то, что было удалено после анализа v27:

- нет exact-title lookup по полному labeled dataset;
- нет hard override по одному ближайшему соседу;
- исключено более широкое правило для сухого горючего с источником воспламенения, давшее false positive.

Абляция показывает, что правила являются существенной частью финального
решения, а не декоративной надстройкой:

| Версия | Состав после v19 | Flammable outer F1 |
|---|---|---:|
| v19 | ML + reference kNN | `0.674221` |
| v34 | v19 + standardized head | `0.681818` |
| v44 | v19 + пять regex | `0.768421` |
| v45 | v19 + head + пять regex | `0.775726` |

При этом outer-оценка regex оптимистична: правила формулировались после анализа
всего released train и не переотбирались внутри fold. Внешнее сравнение есть
только для целых систем: ML/kNN v19 получил public `0.8088923057`, а гибридный
v45 — `0.8142217631`. На private проверялся только v45, поэтому из private score
нельзя выделить вклад regex.

Итоговая характеристика решения — **гибридный мультимодальный классификатор**.
ML/kNN обеспечивает обобщение за пределы пяти паттернов; узкие правила покрывают
однозначные семейства, прямо следующие из определения категории. Заявление, что
правила «не заменяют модель», опирается на сильный public v19 без них, но их
большой локальный вклад также показан явно.

## 10. Объяснение решения

После классификации `Qwen/Qwen3.5-4B` получает название, описание и уже зафиксированный вердикт. LLM отвечает только за краткое объяснение. Если загрузка или генерация завершается ошибкой, детерминированный fallback формирует валидный комментарий без изменения класса. Он не получает пиксели изображения; известная граница доказательности разобрана в [COMMENT_QUALITY.md](COMMENT_QUALITY.md).

Такое разделение важно: генеративная модель не является скрытым вторым классификатором и не создаёт недетерминированность метрики.

## 11. Расширение на новые категории

Pipeline разделяет общую инфраструктуру карточки и category-specific decision
logic. Без изменений переиспользуются:

1. `data.py` — schema adapter, нормализация текста и поиск `images/<id>/`;
2. entity grouping и group-aware split;
3. word/char TF-IDF и Qwen3-VL joint embedding extractor;
4. OOF selection, cache fingerprints и full-data refit;
5. output validation и отделённый от классификации explanation stage.

Отдельно для каждой категории обучаются lexical/VLM heads, выбираются fusion
weights и threshold. Retrieval или узкие rules подключаются только когда это
подтверждается структурой ошибок конкретного направления. Это позволяет новой
категории не менять решения уже развёрнутых heads.

Минимальный путь расширения:

```text
новые размеченные карточки
        ↓
task context + category registration
        ↓
group OOF → category heads → threshold
        ↓
independent holdout / outer audit
        ↓
versioned artifact и общий offline runner
```

В текущем конкурсном runtime список категорий, `TASK_CONTEXT` и часть rule tokens
зафиксированы явно. Поэтому подключение нового направления требует расширить эти
конфигурации и повторить обучение/валидацию. Это описание архитектурных точек
расширения, а не эмпирическое доказательство качества на третьей категории:
такое доказательство потребовало бы новых размеченных данных. Система не
заявляется как zero-shot классификатор неизвестных правил.

## 12. Артефакт и runtime

`official_multimodal.joblib` содержит:

- lexical vectorizers и category heads;
- VLM category heads и frozen blend decisions;
- normalized reference embeddings, labels и IDs для воспламеняемых;
- standardized scaler, linear head и параметры logit-blend;
- пять versioned regex-правил и их provenance;
- provenance полного refit и fingerprint reference bank.

Веса Qwen в архив не входят: runner использует `SHARED_MODELS_PATH`. Runtime зависит только от библиотек официального baseline-образа и не требует `sentence_transformers`.

## 13. Почему не end-to-end LoRA

LoRA выглядел естественным следующим шагом, но редкие положительные группы делали его нестабильным. Qwen3.5 LoRA почти обнулял train loss и давал holdout F1 `0.074`; Qwen3-VL hard-sampled LoRA ухудшал AP сложного fold с `0.363` до `0.209`. Поэтому финальная подтверждённая версия сохраняет frozen encoders: она проще, дешевле и лучше переносится.
