# Как развивалось решение

Этот файл описывает не только удачные версии. Для каждого этапа зафиксированы гипотеза, проверка, решение и урок. Полный журнал без выборочного удаления неудач хранится в [experiments.csv](../experiments.csv).

## Этап 1. Сначала метрика и данные

После открытия данных выяснилось, что задача не является обычной сбалансированной бинарной классификацией:

- категории имеют разные юридические правила;
- positive rate равен 74.5% для `БАД` и 3.6% для воспламеняемых;
- у редкого класса только 113 положительных entity groups;
- в тексте 3 467 точных дубликатов, есть повторяющиеся изображения и шаблоны продавцов.

Поэтому я отказался от random split, реализовал точную official metric и entity-group validation.

## Этап 2. Сильный дешёвый baseline

Первой моделью стала category-specific Logistic Regression над word/char TF-IDF с rule tokens. Пороги выбирались на 5-fold group OOF.

Результат fixed holdout: `0.756857`. Этот baseline остался в финальном ансамбле: он хорошо видит точные маркировки, артикулы и морфологические варианты.

Расширение списка ручных keywords не изменило score, поэтому я не продолжил бесконтрольно наращивать правила.

## Этап 3. Первая VLM и неожиданный data bug

Первая Qwen3-VL ветка использовала masked-mean pooling. Её добавление почти не помогало. Public v2 составил `0.748643`.

При проверке train/inference distribution обнаружилась причина: папка изображений на GPU занимала 387 МБ вместо 9.2 ГБ, а множество файлов имело ровно 262 144 байта. Имена существовали, но содержимое было усечено. Extractor молча переходил на text-only вход, поэтому эксперимент выглядел валидным технически, но обучался не на тех данных.

Исправление:

1. полная повторная синхронизация image corpus;
2. выборочные SHA-256 между локальной и GPU-копией;
3. обязательные `complete`, row fingerprint и zero image failures в cache;
4. отказ от silent mismatch порядка ID.

Главный урок: проверка data contract оказалась полезнее очередной модели.

## Этап 4. Правильный model-card contract

Я заменил ручные vision tokens и masked mean на рекомендованный chat template и last-token pooling. Runtime-версия реализована напрямую через `transformers`, поскольку в официальном образе отсутствовал `sentence_transformers`.

Reference VLM + lexical blend v8 достиг `0.788047` на неизменном holdout, прирост `+0.0302` относительно старой multimodal версии.

Абляции подтвердили необходимость совместного входа:

| Представление | Holdout score |
|---|---:|
| text-only reference | 0.781309 |
| image-only reference | 0.752093 |
| concatenated text + image | 0.787115 |
| **joint reference** | **0.788047** |

## Этап 5. Ошибка full-data threshold selection

В v9 я заново выбрал OOF-порог после перехода к full-data folds. Для воспламеняемых он сдвинулся с `0.331` до `0.630`. Локальный OOF выглядел допустимо, но public упал до `0.745090`.

В v10 я изменил процедуру: архитектура, blend и thresholds замораживаются по честному train OOF/holdout, после чего full refit переобучает только параметры моделей. Public вырос до `0.793388`.

Урок: при 198 positives оценка оптимального порога имеет высокую variance; full refit не должен незаметно переоткрывать model-selection.

## Этап 6. Reference retrieval для редкого класса

Error analysis показал, что линейная голова теряет редкие семейства: топливо в комплекте, пиротехнику, конкретные типы розжига. Я добавил разность максимальной cosine similarity до положительного и отрицательного reference bank.

Параметры выбирались на repeated group OOF, а full bank присоединялся после их фиксации. v19 получил public `0.808892`, улучшив v10 на `+0.015504`, и стал устойчивой основой дальнейших экспериментов.

## Этап 7. Почему локальный v27 не перенёсся

v27 добавлял exact-title lookup, несколько regex и hard-nearest override. Outer proxy вырос до `0.852275`, но public снизился до `0.800964`.

Разбор показал методологическую проблему: 1 802 exact-title mappings были построены по полному labeled dataset, поэтому outer-оценка этой части была оптимистичной. После public-проверки версия отклонена, а основной pipeline возвращён к v19.

Это важный отрицательный результат: высокая локальная метрика не считается доказательством, если feature/lookup был сформирован за пределами fold.

## Этап 8. Проверенные направления после v19

| Гипотеза | Честная проверка | Итог |
|---|---:|---|
| Qwen3.5 retrieval few-shot | AP 0.094 | не различает редкий класс |
| Qwen3.5 LoRA | valid F1 0.074 | сильное переобучение |
| Qwen3.5 hidden-state head | outer F1 0.676 | прирост слишком мал для второй модели |
| PCA/common-component metric | outer F1 0.641 | не перенеслось |
| standardized linear head | outer F1 0.682 | небольшой research-кандидат |
| RBF SVC | outer F1 0.674 | не меняет решения v19 |
| explicit rule-aware embedding prompt | AP 0.438 против 0.458 | общий rule context ухудшает различимость |
| title-only TF-IDF | outer F1 0.671 | AP вырос, thresholded F1 упал |
| Qwen3-VL hard-sampled LoRA | AP 0.209 против 0.363 | усилил train-family shift |

Я сохранял отклонённые эксперименты, потому что для этой задачи они дают три практически важных вывода:

1. большая модель или LoRA не гарантируют перенос при 113 положительных группах;
2. ранжирование и F1 около рабочего порога нужно оценивать отдельно;
3. общий prompt с длинными правилами может сделать embeddings менее различимыми.

## Этап 9. Консервативная надстройка v45

После анализа v27 были построены варианты без exact-title lookup и hard-nearest. Пять узких regex имели 39/39 precision на released data. Они покрывают только однозначные по условию семейства: самостоятельные угольные/топливные брикеты, одноразовые мангалы с углём, газ для портативных плит или горелок, дымовые шашки и брикеты для барбекю.

Отдельная standardized Logistic Regression над исходными joint embeddings дала небольшой независимый сигнал. Её logit смешивается с v19 с весом `0.25`; затем применяются пять правил. Model-selection outer proxy достиг `0.775726` по воспламеняемым и `0.852703` по общей метрике. Для regex-части это оптимистичный proxy, потому что правила отбирались по всему released train, а не заново внутри каждого fold; это ограничение отдельно зафиксировано в [VALIDATION.md](VALIDATION.md).

Public v45 составил `0.8142217631`: прирост `+0.0053294574` относительно v19. Таким образом, перенос подтвердился внешней оценкой. Улучшение меньше локального proxy, что ещё раз показывает высокую variance редкого класса, но направление принято как финальное. На основной закрытой private-части тот же неизменённый submission получил `0.8644397759` и занял 8-е место.

## Правило принятия решений

Эксперимент включался в подтверждённую ветку только если:

1. не использовал labels оцениваемого fold при построении features;
2. улучшал category F1, а не только AP/AUC;
3. не ломал fixed holdout и независимый outer proxy;
4. сохранял официальный runtime contract;
5. после отправки подтверждался public leaderboard.

Именно поэтому финальная история заканчивается не самой сложной моделью, а public-проверенной v45: устойчивой v19-основой и небольшой, объяснимой надстройкой, очищенной от оптимистичных lookup-механизмов.
